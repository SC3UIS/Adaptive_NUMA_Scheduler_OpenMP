# Operational Guide

This document describes the workflow required to reproduce the NUMA scheduling experiments and generate the corresponding performance figures.

## Inputs

* **Sparse matrix**: place `stokes.mtx` in the repository root, or set `SPMV_MTX` to an absolute path.
* **Thread counts**: fixed to 8, 16, 32, 64, and 128.
* **Repetitions**: fixed to 100 with 3 warm-up iterations per run.

## Execution

Run the benchmark workflow from the repository root:

```bash
./scripts/run_perf_metricsV4.sh
```

Optional environment variables:

```bash
SPMV_MTX=/path/to/stokes.mtx
OUTDIR=/path/to/output
```

## Benchmark Workflow

The execution script performs the following steps:

1. Compiles the SpMV benchmark (`SpMV_Kernel.cpp`).
2. Compiles the OMPT scheduler (`NUMA_scheduler_OMPT.cpp`).
3. Executes all benchmark configurations using the predefined thread counts.
4. Collects execution time, bandwidth, and throughput metrics.
5. Generates a consolidated CSV dataset.
6. Produces performance figures automatically.


## Manual Compilation and Execution

The benchmark workflow automates all compilation and execution steps. However, individual components can also be built and executed manually.

### Compile the SpMV Kernel

```bash
clang++ -O3 -ffast-math -fopenmp SpMV_Kernel.cpp -o SpMV_Kernel -ldl
```

### Compile the OMPT Scheduler

```bash
clang++ -std=c++17 -fPIC -shared -fopenmp -pthread \
NUMA_scheduler_OMPT.cpp \
-o NUMA_scheduler.so \
-I/opt/ohpc/pub/libs/hwloc/include \
-L/opt/ohpc/pub/libs/hwloc/lib \
-lhwloc
```

### Baseline Execution

```bash
OMP_PLACES=cores \
OMP_PROC_BIND=spread \
numactl --interleave=all \
./SpMV_Kernel matrix.mtx threads repetitions output.csv
```

Example:

```bash
OMP_PLACES=cores \
OMP_PROC_BIND=spread \
numactl --interleave=all \
./SpMV_Kernel stokes.mtx 32 100 baseline.csv
```

### Scheduler Execution

```bash
OMP_TOOL=enabled \
OMP_TOOL_LIBRARIES=$PWD/NUMA_scheduler.so \
numactl --interleave=all \
./SpMV_Kernel matrix.mtx threads repetitions output.csv
```

Example:

```bash
OMP_TOOL=enabled \
OMP_TOOL_LIBRARIES=$PWD/NUMA_scheduler.so \
numactl --interleave=all \
./SpMV_Kernel stokes.mtx 32 100 scheduler.csv
```

### Command Arguments

| Argument      | Description                                   |
| ------------- | --------------------------------------------- |
| `matrix.mtx`  | Matrix Market input file                      |
| `threads`     | Number of OpenMP threads                      |
| `repetitions` | Number of benchmark repetitions               |
| `output.csv`  | Output file used to store performance metrics |


## Outputs

Benchmark results are stored in:

```text
data/spread_interleave_all.csv
```

The generated CSV contains the following columns:

| Column          | Description                                  |
| --------------- | -------------------------------------------- |
| `Configuration` | Benchmark configuration name                 |
| `Threads`       | Number of OpenMP threads                     |
| `Scheduler`     | Scheduler disabled (`NO`) or enabled (`YES`) |
| `t_min`         | Minimum execution time (ms)                  |
| `stdev_ms`      | Standard deviation (ms)                      |
| `GiB/s`         | Effective memory bandwidth                   |
| `GFLOPS`        | Computational throughput                     |

Runtime logs generated by the scheduler are stored in:

```text
data/ompt_logs/
```

## Plot Generation

Performance figures can be regenerated at any time by running:

```bash
./scripts/run_plot_metrics.sh
```

The plotting workflow uses `plot_numa_results.py` and generates:

```text
plot_gibs.png
plot_gibs.eps

plot_gflops.png
plot_gflops.eps

plot_overhead.png
plot_overhead.eps
```

## Expected Directory Structure

After a successful execution, the repository should contain artifacts similar to:

```text
data/
├── spread_interleave_all.csv
└── ompt_logs/

plots/
├── plot_gibs.eps
├── plot_gibs.png
├── plot_gflops.eps
├── plot_gflops.png
├── plot_overhead.eps
└── plot_overhead.png
```

## System Requirements

* Linux operating system
* NUMA-capable hardware
* Clang with OpenMP support
* hwloc
* numactl
* Python 3
* matplotlib

## Validation

A successful execution should:

1. Generate `data/spread_interleave_all.csv`.
2. Create the scheduler logs in `data/ompt_logs/`.
3. Produce all plot files without errors.
4. Exit with status code `0`.
